# 도서 검색 성능 측정

## 2026-11-19 — 인기 대출·요즘 뜨는 책 로딩

### 원인 조사와 적용 정책

두 목록은 기존에 검색 결과와 5분 메모리 캐시를 공유했다. 앱 재실행·만료·LRU 퇴출 뒤에는 매번 API 응답이 필요했고, 동일 목록의 진행 중 요청도 공유하지 않았다. 급상승은 전날부터 최대 7일을 직렬 탐색하므로 빈 응답이 이어지면 요청 시간이 누적된다. 이들은 코드로 확인한 대기 증폭 요인이다. 간헐적인 장시간 지연 자체는 아래 실측에서는 재현되지 않아 서버 장애나 특정 네트워크를 원인으로 확정하지 않는다.

- 추천 목록 전용 `RecommendedBookCache`를 추가했다. 인기·급상승은 검색어 LRU 캐시에서 분리하고, AppContainer에서 앱 캐시 디렉터리의 `RecommendedBooks-v1` 저장소를 주입한다. SwiftData 스키마와 일반 검색 캐시는 유지한다.
- 응답 완료 후 5분 미만은 재사용, 5분 이상·24시간 미만은 먼저 표시하고 갱신, 24시간 이상·미래 시각은 표시하지 않는다. 캐시 파일은 탭마다 원자적으로 기록하며 손상·저장 실패는 네트워크 성공을 막지 않는다. 정상 빈 응답도 빈 snapshot으로 저장해 과거 도서를 계속 표시하지 않는다.
- 캐시가 없으면 초기 로딩 후 성공·빈 결과·실패 상태로 종료한다. 캐시가 있으면 갱신 상태를 보여주며, 실패해도 행을 유지하고 명시적 재시도를 제공한다. 조회 시각은 캐시 유효성 판단에만 사용하고 화면에는 표시하지 않는다. 캐시 디렉터리는 OS가 정리할 수 있으므로 오프라인 영구 보관 기능으로 보장하지 않는다.
- 정보나루 목록 요청은 개별 10초, 전체 15초로 제한하고 실제 Alamofire 요청을 취소한다. 급상승의 다음 날짜 조회도 같은 전체 예산을 소비한다. 날짜 이동은 정상 빈 응답에만 수행한다. 상세 조회의 제한 시간은 변경하지 않는다.
- 인기·급상승 각각 진행 중 요청을 공유한다. 대기자 하나의 취소는 다른 대기자를 중단하지 않으며, 마지막 대기자 취소 시 통신을 중단한다. 취소된 요청의 늦은 응답은 저장하지 않는다.
- 같은 탭의 반복 탭은 진행 중 조회를 유지한다. 탭 왕복·검색 전환은 generation으로 늦은 응답을 차단한다. 갱신 중에는 표지 보완과 사용자 조작을 막지 않는다.
- 동일 ISBN 순서의 갱신은 기존 셀을 유지하고 내용만 반영한다. 순서가 바뀌면 첫 표시 ISBN과 행 내부 offset을 기준으로 위치를 복원한다. 기존 표지·소개와 진행 중 보완 요청은 ISBN을 기준으로 이어간다.

### 실측과 해석

2026-11-19 개발 Mac에서 동일 HTTPS URL·조회 조건으로 두 API를 각각 5회 직렬 호출했다. 요청 사이에 100ms를 두었고 15초 예산을 적용했다. Python 표준 HTTPS 클라이언트의 요청 시작부터 JSON 수신·파싱까지이며, 앱·기기·UI 성능 측정이나 순수 서버 처리 시간은 아니다. 인증키·요청 URL·도서 내용은 기록하지 않았다.

| 목록 | 표본(ms) | 중앙값 | 범위 | 결과 |
| --- | --- | --- | --- | --- |
| 인기 대출 | 521.4, 413.9, 502.0, 420.4, 481.5 | 481.5ms | 413.9–521.4ms | 5/5 성공, 각각 50건 |
| 요즘 뜨는 책 | 506.0, 409.8, 409.5, 378.8, 400.5 | 409.5ms | 378.8–506.0ms | 5/5 성공, 각각 첫 요청에서 결과 |

급상승 응답은 각 회차에 11/18·11/17·11/16의 세 날짜를 포함했다. 현재 응답에서는 추가 날짜 요청이 필요 없었다. 실제 간헐적 장애의 빈도·최댓값이나 서버 속도 개선율은 이 작은 표본으로 판단하지 않는다.

iPhone Duo / iOS 27.1 Debug 테스트에서 **디스크에 저장한 50권 snapshot을 새 캐시 인스턴스로 복원하고 390×844pt 화면의 첫 셀을 구성**하는 시간을 별도로 측정했다. 네트워크는 완료되지 않은 스텁이며 프로세스·폰트·기기는 이미 실행 중이다. 실제 앱 재시작이나 화면 합성 완료 측정과 구분한다.

| 캐시 상태 | 5회 중앙값 | 범위 |
| --- | --- | --- |
| 5분 이내 | 40.50ms | 36.52–58.81ms |
| 5분 만료 후 갱신 대기 중 | 38.88ms | 38.17–42.01ms |

500ms 목표보다 짧았지만 이는 위 합성 조건의 관찰값이다. 캐시가 전혀 없을 때 외부 API 자체의 응답 속도는 보장하지 않으며, 긴 대기 대신 제한 시간과 재시도 상태로 종료한다. 실제 기기의 앱 재실행·네트워크 변동·표지 완료까지 포함한 전후 5회 비교는 별도 현장 검증 대상이다.

### 회귀 검증

최종 검증: iPhone Duo / iOS 27.1에서 전체 **232개 테스트 통과**(실패 0건). Debug 앱·위젯·테스트 타깃과 generic iOS Simulator Release 앱·위젯 빌드 성공, `git diff --check` 통과. Release 빌드에는 이번에 변경하지 않은 `AdaptiveContentView.swift:85`의 actor 격리 경고가 남아 있다.

기존 `Under_lineTests`에서 디스크 복원·5분/24시간 경계·파일 손상·디스크 기록 실패·빈 결과·요청 공유·대기자별 취소·늦은 성공·갱신 실패·재시도·반복 탭·탭 왕복·갱신 중 ISBN 보완·순서 변경 시 offset 보존을 검증한다. 통신 미응답은 URLProtocol로 재현해 실제 stopLoading 호출을 확인한다. 급상승의 누적 예산 테스트는 120ms 전체 예산과 50ms 빈 응답으로 빠르게 검증하며 실제 측정은 약 123ms였다.

320·390·768pt 화면에 캐시와 갱신 실패를 주입해 안내·재시도·기존 행을 확인하고 XCTest 이미지 첨부물을 남긴다. 작은 화면에서 안내가 잘리던 문제는 무제한 줄바꿈과 내용에 따른 헤더 높이로 수정했다.

재현할 때는 기존 전체 테스트 명령에 아래 식별자를 `-only-testing:Under_lineTests/<식별자>`로 지정할 수 있다.

- `BookSearchViewModelTests/test_recommendationScreen_restoredDiskCacheRendersBeforeNetworkCompletes`: 5회씩 `RecommendationCacheRender` 로그.
- `BookSearchViewModelTests/test_recommendationScreen_rendersStaleFailureAndRetryWithoutClipping`: 너비별 이미지 첨부.
- `Data4LibraryServiceTests/test_popularRequest_hardTimeoutCancelsTransport`: 미응답 통신 취소.
- `Data4LibraryServiceTests/test_trendingRequest_totalBudgetIncludesPreviousEmptyDates`: 날짜 이동의 누적 제한 시간.

## 계측 범위

Debug 빌드에서만 `com.jade.UnderLine` subsystem의 `BookSearchPerformance` category에 기록한다. Xcode 콘솔에서 `stage=`로 필터링하거나 시뮬레이터 로그를 확인한다.

```sh
xcrun simctl spawn booted log show --last 15m --style compact \
  --predicate 'subsystem == "com.jade.UnderLine" AND category == "BookSearchPerformance"'
```

| stage | 시작 → 종료 |
| --- | --- |
| `cacheLookup` | 추천 snapshot 조회(메모리·디스크·미스) |
| `firstListReceived` | 화면 진입·탭 선택 → 첫 snapshot 수신 |
| `responseReceived` | 정보나루 요청 시작 → 응답 수신(네트워크·재개 대기 포함) |
| `decoding` | 정보나루 JSONDecoder 실행 구간 |
| `trendingAttempt` | 급상승 날짜별 요청·디코딩, attempt=전날부터의 일수, responseDays=응답 기간 수 |
| `responseDecoded` | API 요청 직전 → Alamofire 응답 디코딩 후 호출자 복귀 |
| `domainMapping` | DTO 배열의 `toDomain()` 시작 → 전체 변환 완료 |
| `firstCellWillDisplay` | 사용자 요청 시작(추천/검색) 또는 다음 페이지 요청 시작 → 해당 갱신 후 첫 `willDisplayCell` |
| `coverLoaded` | 셀의 Kingfisher `setImage` 호출 → 완료 콜백 |

- `ms`는 단조 증가하는 system uptime으로 측정한 밀리초다.
- API 응답 대기에는 네트워크, 디코딩, 호출자 재개 대기가 포함된다. 순수 서버 처리 시간은 아니다.
- `firstCellWillDisplay`는 화면 합성 완료 시간이 아니다. 4단계부터 페이지 추가 시에는 새로 삽입된 행의 첫 표시를 측정하므로 사용자가 그 행까지 스크롤하기까지의 대기도 포함할 수 있다. 초기 목록 표시와 페이지 추가 표본을 분리해 해석한다.
- 이미지 요청은 셀 구성 시 시작되므로 화면에 보이기 전의 요청도 포함할 수 있다. 완료된 이미지마다 기록하며, 여러 이미지 시간을 합산하지 않는다.
- 추천 목록은 TaskLocal의 임의 generation ID를 API·매핑·테이블·표지에 연결한다. 공유 요청은 처음 시작한 호출자의 ID로 계측한다. 일반 검색 API는 기존 별도 ID를 유지한다. `firstListReceived`의 캐시 표시는 캐시 사용 여부이고 실제 메모리/디스크 구분은 `cacheLookup`을 따른다.
- `source`는 popular/trending/search/isbnEnrichment/data4LibraryDetail/table이다. `count`는 응답·변환·테이블의 도서 수이며 표지에서는 0이다.
- 표지 성공 시 `cache=none/memory/disk`를 기록한다. `none`은 Kingfisher 캐시 미사용이며 OS·HTTP 캐시까지 비어 있다는 뜻은 아니다.
- `outcome=success`만 정상 표시 표본으로 집계한다. failed/cancelled/superseded/notDisplayed/noURL은 따로 센다. 빈 목록에는 첫 셀 로그가 없다.
- 검색어, 책 제목, ISBN, URL, API 키, 응답 본문, 오류 설명은 기록하지 않는다. Release에서는 계측 코드가 제외된다.

## 기준값 수집 절차

1. 동일 기기·OS·Debug 빌드·네트워크를 사용한다. 기기 부팅과 앱 설치가 끝난 뒤 측정한다.
2. 최초 진입은 앱을 종료·재실행하고 도서 검색을 열어 베스트셀러와 표지가 표시될 때까지 기다린다. 이어 고정 검색어 `어린 왕자`로 검색하고 결과·표지 완료를 기다린다. 총 5회 반복한다.
3. 재진입은 같은 앱 실행 안에서 검색 시트를 닫고 다시 열어 같은 검색어로 검색한다. 총 5회 반복한다.
4. 회차별로 API 응답·DTO 변환·첫 셀·표지 시간을 기록하고, 최초 진입과 재진입 각각의 중앙값 및 범위를 비교한다. 표지는 캐시 종류별로 분리한다.
5. 추천 신간 탭과 추가 페이지 로딩도 별도로 확인한다. 빠른 검색·탭 전환, 빈 결과, 화면 닫기 시 실패·교체 표본이 성공 표본에 섞이지 않는지 확인한다.

앱 재실행은 Kingfisher 디스크 캐시를 지우지 않는다. 위 최초 진입은 **프로세스 재시작 기준**이며 완전한 이미지 캐시 미스라고 가정하지 않는다. 완전한 캐시 미스 비교가 필요하면 별도 테스트용 새 시뮬레이터를 사용한다. 각 후속 단계도 같은 조건으로 비교한다. Debug 로깅 자체의 비용이 포함되므로 배포 빌드의 절대 성능으로 해석하지 않는다.

## 1단계 검증 상태

2026-09-16 검증 결과:

- Debug·Release의 generic iOS Simulator 앱·위젯 빌드 성공.
- Debug 실행 파일에서 계측 식별자 확인, Release 실행 파일에서는 제외됨을 확인.
- iPhone 17 Pro / iOS 26.5 시뮬레이터에 Debug 앱 설치 및 실행 명령 성공. 검색 화면 조작 검증과는 구분한다.
- `git diff --check` 통과.
- 기존 `ReadingActivityManager`의 actor 격리 경고와 앱(1.2.4)·위젯(1.2.3)의 버전 불일치 경고는 이번 수정 범위에 포함하지 않음.

계측을 추가했으며 검색·페이지네이션·HTML 변환·이미지 로딩 정책은 유지한다. 시뮬레이터 UI 제어 도구의 타임아웃으로 최초 진입 및 재진입 각 5회의 기준값은 아직 수집하지 못했다. 실제 지연 수치와 개선율은 미확정이며, 위 절차로 기준값을 수집해야 1단계의 측정 완료 조건을 충족한다.

## 2단계 — 원격 목록 메모리 캐시

- 공유 `BookRepository`가 베스트셀러, 추천 신간 페이지, 검색어·페이지별로 성공 결과를 재사용한다. 검색 결과의 `totalResults`와 빈 성공 결과도 저장한다.
- 유효 기간은 응답 완료부터 300초이며, 캐시 조회로 연장하지 않는다. 최대 30개 항목을 보관하고 만료 항목을 정리한 뒤 가장 오래 사용하지 않은 항목부터 제거한다.
- 검색어의 앞뒤 공백·개행만 제거한다. 내부 공백과 대소문자는 유지하며 첫 검색·다음 페이지·캐시 키에 같은 정규화 규칙을 사용한다.
- 실패·취소 응답은 저장하지 않는다. API가 취소를 무시하고 성공을 반환해도 Repository에서 취소 여부를 다시 확인한다.
- 캐시는 앱 프로세스 메모리에만 존재한다. 도서 상세 조회는 캐시하지 않으며, 동시에 시작된 캐시 미스 요청을 하나로 합치지는 않는다.
- 캐시 적중 시 API 및 DTO 변환을 건너뛰므로 `responseDecoded`/`domainMapping` 로그가 발생하지 않는다. 테이블·표지 계측은 계속 수행하며 표지 캐시는 별도다.

`Under_lineTests`는 실제 API와 영구 저장소를 사용하지 않는다. 가짜 API 호출 횟수, 제어 가능한 시계, 메모리 SwiftData 컨테이너로 재사용·만료·LRU·취소 및 ViewModel의 검색어 일관성을 검증한다.

```sh
xcodebuild -project Under_line.xcodeproj -scheme Under_line \
  -destination 'platform=iOS Simulator,id=<시뮬레이터 UUID>' \
  -parallel-testing-enabled NO test
```

1단계의 실제 UI 기준값은 여전히 미수집 상태다. API 호출 생략 여부를 확인하는 자동화 테스트와 실제 화면 표시 시간 측정은 구분한다.

검증 결과: iPhone 17 Pro / iOS 26.5에서 앱·위젯·테스트 타깃 빌드 및 14개 테스트 통과(실패 0건). `git diff --check` 통과. 기존 actor 격리·앱/위젯 버전 불일치 경고는 유지된다.

## 3단계 — 표지와 셀 렌더링

- 48×64pt 표지 영역에 화면 배율을 반영해 다운샘플링한다. 3배율의 3:4 표지는 144×192픽셀로 처리한다. 이미지 비율을 유지하며 픽셀 크기를 processor 식별자에 포함한다.
- 셀과 선로딩은 같은 processor·배율·기본 Kingfisher 캐시를 사용한다. 선로딩에는 디스크 캐시 결과를 메모리로 올리는 옵션을 추가한다. 원본 URL은 유지하므로 다운로드 바이트 감소를 의미하지 않는다.
- 표시 영역 다음 10개 행 안의 중복되지 않는 표지를 최대 2개씩 준비한다. 화면 밖의 모든 도서를 한 번에 요청하지 않는다. 표시 셀 자체의 이미지 요청은 이 선로딩 개수 제한과 별도다.
- 스크롤로 선로딩 범위가 이동하면 범위를 벗어난 요청만 중단하고 겹치는 요청은 유지한다. 목록 갱신·새 목록 로딩·화면 이탈 시 선로딩을 중단하며, 중단된 요청의 늦은 콜백은 새 요청에 영향을 주지 않는다.
- 같은 선로딩 범위에서 실패를 반복 재시도하지 않는다. 실제 셀의 이미지 요청은 별도로 실행한다.
- 셀 재사용 시 이미지 다운로드와 Kingfisher 요청 식별자, 이미지, 도서 참조·등록 콜백을 초기화한다. 제목·저자는 표지 완료를 기다리지 않는다.
- 순위 유무에 따른 leading 제약을 미리 만들고 전환한다. 카드 bounds가 변경될 때만 그림자 경로를 갱신하고 자동 행 높이는 유지한다.

검증 결과: iPhone 17 Pro / iOS 26.5에서 앱·위젯·테스트 타깃 빌드와 총 21개 테스트 통과(기존 14개, 신규 7개). 신규 테스트는 선로딩 범위·동시 실행 제한, 겹치는 요청 유지, 중단 후 늦은 콜백, 중복·누락 URL, 마지막 행·빈 목록, 배율 변경, 실제 다운샘플링 픽셀 크기를 검증한다. 네트워크 선로딩은 가짜 작업으로 검증하고 다운샘플링은 실제 Kingfisher processor로 검증했다.

실제 화면의 빠른 스크롤·셀 재사용에 대한 시각 검증 및 캐시 유무별 지연 시간 비교는 아직 수행하지 못했다. 앞선 1단계 기준값도 미수집이므로 실제 개선율은 미확정이다.

## 4단계 — 페이지 선요청과 부분 갱신

- 마지막 5개 행에 진입하면 다음 페이지를 요청한다. 여러 표시·스크롤 이벤트는 다음 메인 큐 작업으로 합쳐 레이아웃 반영 후 판단한다.
- 성공으로 목록이 갱신된 뒤에도 하단 영역이 보이면 다시 판단한다. 짧은 목록은 추가 스크롤 이벤트 없이 다음 페이지를 준비할 수 있다.
- 같은 하단 영역에 머무르는 동안 요청을 반복하지 않는다. 실패 시 기존 행을 유지하고, 하단 영역을 벗어났다가 재진입하면 같은 페이지를 재시도한다. 일시적으로 표시 행을 알 수 없는 레이아웃 상태는 재시도 조건을 초기화하지 않는다.
- ViewModel은 검색·추천 목록·추가 페이지에 하나의 교체 가능한 요청을 사용한다. 새 검색·목록 선택마다 세대 ID를 갱신하고 이전 요청을 취소한다. 같은 검색어나 탭으로 돌아와도 이전 응답·오류가 현재 로딩 상태와 결과를 변경하지 않는다.
- 페이지 요청은 한 번에 하나만 진행하며 성공했을 때만 현재 페이지를 전진시킨다. 검색 최대 200개·4페이지, 추천 신간 최대 50개·5페이지를 유지한다. 빈 후속 페이지 또는 짧은 후속 페이지에서는 종료한다.
- Output에 전체 snapshot과 `replace`/`append(from:)`를 담은 `listUpdates`를 추가했다. 기존 `books` 출력은 유지한다. 초기·검색·탭 교체는 전체 reload 및 최상단 이동, 페이지 추가는 새 행만 애니메이션 없이 삽입하고 기존 스크롤 위치를 유지한다.
- 데이터소스에 이전 snapshot이 없는 상태에서 append를 받으면 전체 snapshot으로 복원한다. 행 식별에 ISBN을 사용하지 않으므로 ISBN이 중복되어도 삽입 식별자 충돌은 없다.
- 페이지 추가 시 기존 표지 선로딩을 일괄 중단하지 않고 갱신된 표시 범위에 맞춰 조정한다. HTML 문자열 변환은 5단계 대상으로 그대로 남겨 둔다.

검증 결과: iPhone 17 Pro / iOS 26.5에서 앱·위젯·테스트 타깃 빌드와 총 34개 테스트 통과(기존 21개, 신규 13개). 취소를 무시하는 가짜 Repository로 이전 검색·탭·페이지 응답 및 오류를 검증했다. 중복 요청, 실패 후 동일 페이지 재시도, 결과 상한, 빈/짧은 후속 페이지와 하단 진입 조건을 확인했다. 실제 `UITableView`를 사용하는 테스트에서 append 시 reload 미호출, 새 행 범위 및 스크롤 위치 유지를 확인했다. `git diff --check` 통과.

앱 전체 화면에서의 시각 검증과 네트워크 조건별 체감 지연 비교는 미완료다. 실제 개선율은 아직 보고하지 않는다.

## 5단계 — HTML 문자열 변환

- DTO의 제목과 설명에 적용하던 동기 HTML 파서를 `HTMLTextDecoder`로 분리했다. 도서 검색 셀은 설명을 표시하지 않지만 등록·상세 화면에서 같은 `Book`을 사용하므로 설명 변환 자체는 유지한다.
- HTML 태그가 없는 문자열은 한 번 순회하며 `amp`, `lt`, `gt`, `quot`, `apos`, `nbsp`와 유효한 10진수·16진수 Unicode 문자 참조를 변환한다. `&amp;amp;` 같은 중첩 값은 한 번만 해제한다.
- 태그가 있거나 지원 목록 밖의 올바른 이름 엔티티가 있으면 기존 `NSAttributedString` HTML 파서로 처리한다. 공백·세미콜론 누락, 빈 숫자, 잘못된 숫자 및 유효하지 않은 Unicode scalar는 원문을 보존한다.
- 빠른 경로는 태그·엔티티가 없는 일반 한글을 그대로 반환한다. 검색어, 제목, ISBN, 설명 등의 원문은 성능 로그에 남기지 않는다.

검증 결과: iPhone 17 Pro / iOS 26.5 Debug에서 전체 44개 테스트를 통과한 뒤 비ASCII 태그 판별을 보완하고 HTML 변환기 테스트 11개를 다시 통과했다. 일반 한글, 지원 엔티티, 10진수·16진수 문자 참조, 중첩·잘못된 참조, 실제 HTML·지원 밖 엔티티 폴백, 일반·비ASCII 부등호 및 DTO 전체 매핑을 검증했다. 최종 동일 입력 100회 단일 측정에서 빠른 경로 약 1.17ms, 기존 HTML 파서 약 451.57ms가 기록됐다. 이 수치는 Debug 시뮬레이터의 합성 벤치마크이며 실제 화면 개선율로 해석하지 않는다. Release 앱·위젯 빌드와 `git diff --check`도 통과했다.

1단계의 실제 화면 기준값이 없으므로 API 응답 이후의 전체 단축 시간은 확정하지 않는다. Debug의 `domainMapping` 계측으로 실제 응답별 변환 시간을 계속 비교할 수 있다.

## 목록 메타데이터 갱신 중 스크롤 유지

- 인기 대출·요즘 뜨는 책의 표지/소개 보완은 `update(rows:)`로 전달한다. 데이터소스는 전체 snapshot을 갱신한 뒤 표시 중인 기존 셀의 메타데이터만 변경한다. 이 경로에서는 `reloadRows`나 `setContentOffset`을 호출하지 않는다.
- 같은 표지 URL은 다시 요청하지 않는다. 접힌 소개는 문자열만 보관하고, 펼칠 때 attributed text와 높이를 계산한다. 같은 소개·너비의 측정값은 재사용한다.
- 펼친 소개의 응답이 드래그·감속 중 도착하면 표지만 반영하고 소개 갱신과 행 높이 재계산은 스크롤 종료까지 보류한다. 반영 직전에 현재 목록·펼친 행·셀의 ISBN을 확인하며, 목록 교체나 다른 행 선택 시 보류 상태를 폐기한다.
- 비교 시에는 동일 기기에서 인기 대출 목록의 최초 하향 → 상향 → 동일 구간 재하향을 수행하고 요즘 뜨는 책·검색 결과와 비교한다. 프로세스 재시작은 이미지 디스크 캐시 초기화와 구분한다.
- Instruments의 Animation Hitches와 Time Profiler에서 끊김 구간의 셀 갱신·텍스트 측정을 비교한다. 자동화 테스트의 셀/offset 보존 검증은 실제 화면의 프레임 성능 측정을 대신하지 않는다.

검증 결과(2026-11-14): iPhone Duo / iOS 27.1 시뮬레이터에서 앱·위젯·테스트 타깃 빌드와 전체 162개 테스트 통과(실패·건너뜀 0건). 신규 테스트는 기존 셀과 offset 유지, 행 재로드/offset 설정 미호출, 화면 밖 snapshot·중복 ISBN 반영, 접힌 소개의 지연 구성, 펼침·버튼 콜백·재사용 상태 보존을 확인한다. `git diff --check` 통과. 실제 화면의 최초/반복 스크롤 비교와 Instruments 프레임 측정은 아직 수행하지 않았다.

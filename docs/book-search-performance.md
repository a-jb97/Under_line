# 도서 검색 성능 측정

## 계측 범위

Debug 빌드에서만 `com.jade.UnderLine` subsystem의 `BookSearchPerformance` category에 기록한다. Xcode 콘솔에서 `stage=`로 필터링하거나 시뮬레이터 로그를 확인한다.

```sh
xcrun simctl spawn booted log show --last 15m --style compact \
  --predicate 'subsystem == "com.jade.UnderLine" AND category == "BookSearchPerformance"'
```

| stage | 시작 → 종료 |
| --- | --- |
| `responseDecoded` | API 요청 직전 → Alamofire 응답 디코딩 후 호출자 복귀 |
| `domainMapping` | DTO 배열의 `toDomain()` 시작 → 전체 변환 완료 |
| `firstCellWillDisplay` | Controller의 목록 수신 → 해당 갱신 후 첫 `willDisplayCell` |
| `coverLoaded` | 셀의 Kingfisher `setImage` 호출 → 완료 콜백 |

- `ms`는 단조 증가하는 system uptime으로 측정한 밀리초다.
- API 응답 대기에는 네트워크, 디코딩, 호출자 재개 대기가 포함된다. 순수 서버 처리 시간은 아니다.
- `firstCellWillDisplay`는 화면 합성 완료 시간이 아니다. 4단계부터 페이지 추가 시에는 새로 삽입된 행의 첫 표시를 측정하므로 사용자가 그 행까지 스크롤하기까지의 대기도 포함할 수 있다. 초기 목록 표시와 페이지 추가 표본을 분리해 해석한다.
- 이미지 요청은 셀 구성 시 시작되므로 화면에 보이기 전의 요청도 포함할 수 있다. 완료된 이미지마다 기록하며, 여러 이미지 시간을 합산하지 않는다.
- API 요청과 DTO 변환은 같은 임의 `id`를 사용한다. 테이블 갱신과 그 갱신에 속한 표지는 별도의 공통 `id`를 사용한다. API와 UI의 id는 직접 연결되지 않는다.
- `source`는 bestseller/newSpecial/search/table이다. `count`는 응답·변환·테이블의 도서 수이며 표지에서는 0이다.
- 표지 성공 시 `cache=none/memory/disk`를 기록한다. `none`은 Kingfisher 캐시 미사용이며 OS·HTTP 캐시까지 비어 있다는 뜻은 아니다.
- `outcome=success`만 정상 표시 표본으로 집계한다. failed/cancelled/superseded/notDisplayed/noURL은 따로 센다. 빈 목록에는 첫 셀 로그가 없다.
- 검색어, 책 제목, ISBN, URL, API 키, 응답 본문, 오류 설명은 기록하지 않는다. Release에서는 계측 코드가 제외된다.

## 기준값 수집 절차

1. 동일 기기·OS·Debug 빌드·네트워크를 사용한다. 기기 부팅과 앱 설치가 끝난 뒤 측정한다.
2. 최초 진입은 앱을 종료·재실행하고 도서 검색을 열어 베스트셀러와 표지가 표시될 때까지 기다린다. 이어 고정 검색어 `어린 왕자`로 검색하고 결과·표지 완료를 기다린다. 총 5회 반복한다.
3. 재진입은 같은 앱 실행 안에서 검색 시트를 닫고 다시 열어 같은 검색어로 검색한다. 총 5회 반복한다.
4. 회차별로 API 응답·DTO 변환·첫 셀·표지 시간을 기록하고, 최초 진입과 재진입 각각의 중앙값 및 범위를 비교한다. 표지는 캐시 종류별로 분리한다.
5. 추천 신간 탭과 추가 페이지 로딩도 별도로 확인한다. 빠른 검색·탭 전환, 빈 결과, 화면 닫기 시 실패·교체 표본이 성공 표본에 섞이지 않는지 확인한다.

앱 재실행은 Kingfisher 디스크 캐시를 지우지 않는다. 위 최초 진입은 **프로세스 재시작 기준**이며 완전한 이미지 캐시 미스라고 가정하지 않는다. 완전한 캐시 미스 비교가 필요하면 별도 테스트용 새 시뮬레이터를 사용한다. 각 후속 단계도 같은 조건으로 비교한다. Debug 로깅 자체의 비용이 포함되므로 배포 빌드의 절대 성능으로 해석하지 않는다.

## 1단계 검증 상태

2026-09-16 검증 결과:

- Debug·Release의 generic iOS Simulator 앱·위젯 빌드 성공.
- Debug 실행 파일에서 계측 식별자 확인, Release 실행 파일에서는 제외됨을 확인.
- iPhone 17 Pro / iOS 26.5 시뮬레이터에 Debug 앱 설치 및 실행 명령 성공. 검색 화면 조작 검증과는 구분한다.
- `git diff --check` 통과.
- 기존 `ReadingActivityManager`의 actor 격리 경고와 앱(1.2.4)·위젯(1.2.3)의 버전 불일치 경고는 이번 수정 범위에 포함하지 않음.

계측을 추가했으며 검색·페이지네이션·HTML 변환·이미지 로딩 정책은 유지한다. 시뮬레이터 UI 제어 도구의 타임아웃으로 최초 진입 및 재진입 각 5회의 기준값은 아직 수집하지 못했다. 실제 지연 수치와 개선율은 미확정이며, 위 절차로 기준값을 수집해야 1단계의 측정 완료 조건을 충족한다.

## 2단계 — 원격 목록 메모리 캐시

- 공유 `BookRepository`가 베스트셀러, 추천 신간 페이지, 검색어·페이지별로 성공 결과를 재사용한다. 검색 결과의 `totalResults`와 빈 성공 결과도 저장한다.
- 유효 기간은 응답 완료부터 300초이며, 캐시 조회로 연장하지 않는다. 최대 30개 항목을 보관하고 만료 항목을 정리한 뒤 가장 오래 사용하지 않은 항목부터 제거한다.
- 검색어의 앞뒤 공백·개행만 제거한다. 내부 공백과 대소문자는 유지하며 첫 검색·다음 페이지·캐시 키에 같은 정규화 규칙을 사용한다.
- 실패·취소 응답은 저장하지 않는다. API가 취소를 무시하고 성공을 반환해도 Repository에서 취소 여부를 다시 확인한다.
- 캐시는 앱 프로세스 메모리에만 존재한다. 도서 상세 조회는 캐시하지 않으며, 동시에 시작된 캐시 미스 요청을 하나로 합치지는 않는다.
- 캐시 적중 시 API 및 DTO 변환을 건너뛰므로 `responseDecoded`/`domainMapping` 로그가 발생하지 않는다. 테이블·표지 계측은 계속 수행하며 표지 캐시는 별도다.

`Under_lineTests`는 실제 API와 영구 저장소를 사용하지 않는다. 가짜 API 호출 횟수, 제어 가능한 시계, 메모리 SwiftData 컨테이너로 재사용·만료·LRU·취소 및 ViewModel의 검색어 일관성을 검증한다.

```sh
xcodebuild -project Under_line.xcodeproj -scheme Under_line \
  -destination 'platform=iOS Simulator,id=<시뮬레이터 UUID>' \
  -parallel-testing-enabled NO test
```

1단계의 실제 UI 기준값은 여전히 미수집 상태다. API 호출 생략 여부를 확인하는 자동화 테스트와 실제 화면 표시 시간 측정은 구분한다.

검증 결과: iPhone 17 Pro / iOS 26.5에서 앱·위젯·테스트 타깃 빌드 및 14개 테스트 통과(실패 0건). `git diff --check` 통과. 기존 actor 격리·앱/위젯 버전 불일치 경고는 유지된다.

## 3단계 — 표지와 셀 렌더링

- 48×64pt 표지 영역에 화면 배율을 반영해 다운샘플링한다. 3배율의 3:4 표지는 144×192픽셀로 처리한다. 이미지 비율을 유지하며 픽셀 크기를 processor 식별자에 포함한다.
- 셀과 선로딩은 같은 processor·배율·기본 Kingfisher 캐시를 사용한다. 선로딩에는 디스크 캐시 결과를 메모리로 올리는 옵션을 추가한다. 원본 URL은 유지하므로 다운로드 바이트 감소를 의미하지 않는다.
- 표시 영역 다음 10개 행 안의 중복되지 않는 표지를 최대 2개씩 준비한다. 화면 밖의 모든 도서를 한 번에 요청하지 않는다. 표시 셀 자체의 이미지 요청은 이 선로딩 개수 제한과 별도다.
- 스크롤로 선로딩 범위가 이동하면 범위를 벗어난 요청만 중단하고 겹치는 요청은 유지한다. 목록 갱신·새 목록 로딩·화면 이탈 시 선로딩을 중단하며, 중단된 요청의 늦은 콜백은 새 요청에 영향을 주지 않는다.
- 같은 선로딩 범위에서 실패를 반복 재시도하지 않는다. 실제 셀의 이미지 요청은 별도로 실행한다.
- 셀 재사용 시 이미지 다운로드와 Kingfisher 요청 식별자, 이미지, 도서 참조·등록 콜백을 초기화한다. 제목·저자는 표지 완료를 기다리지 않는다.
- 순위 유무에 따른 leading 제약을 미리 만들고 전환한다. 카드 bounds가 변경될 때만 그림자 경로를 갱신하고 자동 행 높이는 유지한다.

검증 결과: iPhone 17 Pro / iOS 26.5에서 앱·위젯·테스트 타깃 빌드와 총 21개 테스트 통과(기존 14개, 신규 7개). 신규 테스트는 선로딩 범위·동시 실행 제한, 겹치는 요청 유지, 중단 후 늦은 콜백, 중복·누락 URL, 마지막 행·빈 목록, 배율 변경, 실제 다운샘플링 픽셀 크기를 검증한다. 네트워크 선로딩은 가짜 작업으로 검증하고 다운샘플링은 실제 Kingfisher processor로 검증했다.

실제 화면의 빠른 스크롤·셀 재사용에 대한 시각 검증 및 캐시 유무별 지연 시간 비교는 아직 수행하지 못했다. 앞선 1단계 기준값도 미수집이므로 실제 개선율은 미확정이다.

## 4단계 — 페이지 선요청과 부분 갱신

- 마지막 5개 행에 진입하면 다음 페이지를 요청한다. 여러 표시·스크롤 이벤트는 다음 메인 큐 작업으로 합쳐 레이아웃 반영 후 판단한다.
- 성공으로 목록이 갱신된 뒤에도 하단 영역이 보이면 다시 판단한다. 짧은 목록은 추가 스크롤 이벤트 없이 다음 페이지를 준비할 수 있다.
- 같은 하단 영역에 머무르는 동안 요청을 반복하지 않는다. 실패 시 기존 행을 유지하고, 하단 영역을 벗어났다가 재진입하면 같은 페이지를 재시도한다. 일시적으로 표시 행을 알 수 없는 레이아웃 상태는 재시도 조건을 초기화하지 않는다.
- ViewModel은 검색·추천 목록·추가 페이지에 하나의 교체 가능한 요청을 사용한다. 새 검색·목록 선택마다 세대 ID를 갱신하고 이전 요청을 취소한다. 같은 검색어나 탭으로 돌아와도 이전 응답·오류가 현재 로딩 상태와 결과를 변경하지 않는다.
- 페이지 요청은 한 번에 하나만 진행하며 성공했을 때만 현재 페이지를 전진시킨다. 검색 최대 200개·4페이지, 추천 신간 최대 50개·5페이지를 유지한다. 빈 후속 페이지 또는 짧은 후속 페이지에서는 종료한다.
- Output에 전체 snapshot과 `replace`/`append(from:)`를 담은 `listUpdates`를 추가했다. 기존 `books` 출력은 유지한다. 초기·검색·탭 교체는 전체 reload 및 최상단 이동, 페이지 추가는 새 행만 애니메이션 없이 삽입하고 기존 스크롤 위치를 유지한다.
- 데이터소스에 이전 snapshot이 없는 상태에서 append를 받으면 전체 snapshot으로 복원한다. 행 식별에 ISBN을 사용하지 않으므로 ISBN이 중복되어도 삽입 식별자 충돌은 없다.
- 페이지 추가 시 기존 표지 선로딩을 일괄 중단하지 않고 갱신된 표시 범위에 맞춰 조정한다. HTML 문자열 변환은 5단계 대상으로 그대로 남겨 둔다.

검증 결과: iPhone 17 Pro / iOS 26.5에서 앱·위젯·테스트 타깃 빌드와 총 34개 테스트 통과(기존 21개, 신규 13개). 취소를 무시하는 가짜 Repository로 이전 검색·탭·페이지 응답 및 오류를 검증했다. 중복 요청, 실패 후 동일 페이지 재시도, 결과 상한, 빈/짧은 후속 페이지와 하단 진입 조건을 확인했다. 실제 `UITableView`를 사용하는 테스트에서 append 시 reload 미호출, 새 행 범위 및 스크롤 위치 유지를 확인했다. `git diff --check` 통과.

앱 전체 화면에서의 시각 검증과 네트워크 조건별 체감 지연 비교는 미완료다. 실제 개선율은 아직 보고하지 않는다.
